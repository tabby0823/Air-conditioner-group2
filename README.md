## 开发协作规则
1. main 分支是稳定主分支，**禁止直接 commit/push 到 main**
2. 新开发分支命名：`feature/xxx`；bug 修复分支：`bugfix/xxx`
3. Commit 格式规范：
   - feat: 新增功能
   - fix: 修复 bug
   - docs: 更新文档
4. 开发前先看对应 Issue，分支和 Issue 对应
5. 所有修改必须提交 Pull Request，至少 2 人评审通过才能合并；**不能合并自己的 PR**

## PR 交叉评审安排
- B 的 PR：组长 A + D 评审
- C 的 PR：组长 A + B 评审
- D 的 PR：组长 A + C 评审
- A 的 PR：B + C 评审，由 B 或 C 合并，A 不能合并自己代码

日志存储模块：
功能：实现检测数据持久保存，日志字段与interface.md保持一致
配套文档：docs/日志格式说明文档
partD实现的功能：
1. 向这个设备服务端发起网络请求，读取设备的实时状态：有没有人在线、运行时长
2. 获取设备日志（可以指定条数 limit），拿到带时间戳、级别、消息的运行日志
3. 获取统计数据：wifi错误、雷达错误、自动关机次数等故障统计
4. 发送POST请求，模拟切换「有人/无人」状态（用来调试B模块，不用真实传感器触发）
5. 增加了基础异常捕获：网络超时、连接失败、接口返回非JSON等情况，不会直接崩溃
简单一句话总结：
这是一个调试客户端，用来读取这套感知设备的状态、日志、统计，并且支持模拟人为触发有人/无人状态，适合开发、测试、调试这个B模块系统。
